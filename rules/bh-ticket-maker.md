# bh-ticket-maker

Jira 티켓 생성이 필요하거나 사용자가 티켓 생성을 요청할 때, 직접 Jira API를 임의로 호출하거나 브라우저 수동 생성을 요청하는 대신 로컬 CLI 도구 `bh-ticket-maker`를 사용한다.

## When (Read on demand)

- 신규 Jira 티켓 생성이 필요할 때
- 결함/버그 리포트 티켓 생성을 요청받았을 때
- 작업(Task) 또는 개발 요청 티켓 생성을 요청받았을 때
- 티켓 기반 작업(ticket-driven work) 진행 중 브랜치/작업용 티켓이 없어 신규 발급이 필요할 때

## 기본 정책 및 제약 (불변식)

| 항목 | 기본값 | 비고 |
|------|--------|------|
| **프로젝트** | `COMPANY` | 필요 시 지정 프로젝트 키 입력 (`-p`) |
| **이슈 유형** | `결함` | 프로젝트에 따라 `Defect`, `버그` 등으로 자동 매핑 (`-t`) |
| **업무 담당자** | 기본 사용자 | 프로필/사번 기준 자동 할당. 미지정 필요 시 `--no-assignee` |
| **시작일 / 종료일** | **미지원 (전송 금지)** | 날짜 필드는 일체 요구하거나 Jira로 전달하지 않는다 |
| **이슈 설명** | 다중 행 지원 | `-d`, `-f`, 파이프(`cat ... | bh-ticket-maker`), 터미널 멀티라인 지원 |

## CLI 명령어 규격

도구 경로: `~/bin/bh-ticket-maker` (PATH 등록)

```bash
bh-ticket-maker [옵션]
  -s, --summary <TEXT>        이슈 제목 (요약, 필수)
  -d, --desc <TEXT>           이슈 설명 (여러 줄은 \n 사용 가능)
  -f, --file <PATH>           설명으로 사용할 파일 경로
  -p, --project <KEY>         Jira 프로젝트 키 (기본값: COMPANY)
  -t, --type <NAME>           이슈 유형 (기본값: 결함)
  -a, --assignee <USER/ID>    담당자 이름 또는 사번 (기본값: 기본 담당자)
      --no-assignee           담당자 미지정(Unassigned)
  -y, --yes                   생성 전 확인 프롬프트 건너뛰기
  -o, --open                  생성 완료 후 브라우저에서 티켓 열기
      --dry-run               실제 생성 없이 요청 페이로드만 확인
  -h, --help                  도움말 출력
```

## 에이전트 실행 지침

에이전트가 티켓 생성을 대행할 때는 **비대화형 플래그(`-y`, `-s`, `-d` 등)**를 사용하여 터미널 입력을 블로킹하지 않고 즉시 실행한다.

### 1. 결함 티켓 생성 (기본값 적용)

```bash
bh-ticket-maker -s "주문서 쿠폰 적용 시 할인율 계산 오류" -d "상세 재현 경로:\n1. 장바구니 담기\n2. 쿠폰 선택\n3. 할인율 불일치" -y
```

### 2. 특정 프로젝트 작업(Task) 티켓 생성

```bash
bh-ticket-maker -p COMPANY -t "작업" -s "프론트엔드 빌드 최적화" -d "빌드 속도 개선 및 번들 크기 경량화 작업" -y
```

### 3. 생성 완료 후 보고

생성 완료 시 반환된 티켓 키(`COMPANY-XXXXX`) 및 URL(`https://jira.company.com/browse/COMPANY-XXXXX`)을 사용자에게 확인 보고하고, 티켓 번호를 기반으로 브랜치 분기 또는 후속 작업을 진행한다.
