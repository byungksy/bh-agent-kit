# bh-status-board

Jira 티켓을 여러 에이전트 세션에서 진행할 때, 실제 작업 세션을 `bh-현황판`에 확정 연결하고 주요 진척을 기록한다.

## 적용 시점

- Codex, agy/Antigravity, Cursor Agent, Claude 등에서 Jira 티켓 작업을 시작할 때
- 사용자 요청·브랜치·작업 문맥을 확인해 현재 실제 작업 대상 티켓을 특정할 수 있을 때

## 규칙

1. 작업 시작 시 현재 작업 대상 티켓을 확인하고 `attach` 명령을 도구로 실행한다. 티켓 목록·인용·요약에 등장한 키만으로 실제 작업 대상이라고 판단하지 않는다.
   ```bash
   bh-현황판 attach --agent <codex|agy|cursor|claude> --ticket <TICKET-123>
   ```
2. 현황판이 대화 로그에서 자동 추출한 세션은 `후보`다. 후보 표시나 티켓 키 언급은 확정 연결의 근거가 아니며, 후보를 확인했다는 이유로 연결됐다고 말하지 않는다. `attach` 또는 티켓을 지정한 `report`를 실행해야 확정 연결된다.
3. 한 세션에서 여러 티켓이 언급되면 이번 작업 대상만 연결한다. 대상이 불분명하면 임의로 연결하지 말고 사용자에게 확인한다.
4. 주요 단계가 끝나면 실제 완료 내용과 확인 가능한 근거를 보고한다.
   ```bash
   bh-현황판 report --agent <codex|agy|cursor|claude> --ticket <TICKET-123> \
     --note '<완료한 일>' --evidence '<검증 근거>'
   ```
5. `--progress 0~100`은 티켓의 완료 기준과 현재 상태로 전체 진척률을 판단할 수 있을 때만 추가한다. 세션의 기여량이나 진척률을 추정하지 않는다.
6. 세션 ID를 CLI가 자동 식별하지 못하면 현재 대화의 정확한 ID를 `--session <ID>`로 전달한다. 세션 ID를 추측하거나 다른 세션 ID를 재사용하지 않는다.
7. 인증값, 원문 대화, 개인 기록을 note/evidence에 복사하지 않는다. 명령을 사용할 수 없거나 실행이 실패하면 연결·보고가 됐다고 주장하지 말고 그 사실을 알린다.
