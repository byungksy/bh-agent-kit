# Prompt Auto Enhance (모호한 요청 시 조건부 자동 강화)

## When (발동 조건)

사용자의 요청이 다음 **모호한 작업 조건**에 해당할 때만 선별적으로 발동한다:

1. 발화가 1~2문장 내외로 짧고, 구체적인 대상(`@파일`, 경로, 심볼)이나 명확한 완료 기준이 누락된 구현·수정·작업 요청일 때
   - 예: "이거 고쳐줘", "장바구니 에러 잡아봐", "성능 좀 올려줘", "이 기능 추가해봐"
2. 또는 명시적인 트리거 키워드가 있을 때 (`/prompt-enhance`, "프롬프트 강화", "다듬어서 실행해")

### 해당 없음 (발동 금지 / Fast-path)

- 단순 조회·설명·질문·사실 확인 ("이 함수 뭐야?", "PR 머지 상태 확인해줘", "로그 보여줘")
- 대상 파일이나 수정 위치, 값이 명확히 지정된 요청 ("@foo.ts 20번째 줄 오타 수정해줘")
- 사용자의 확인·진행 단답 ("진행", "응", "다음", "커밋해")
- 이미 `00-inquiry-first` 게이트나 승인된 플랜 하에서 진행 중인 작업

## Contract

1. **임의 추측성 코드(Speculative Code) 원천 차단**:
   - 모호한 발화만 믿고 혼자 넘겨짚어 대규모 코드 수정이나 임의 구현에 착수하지 않는다.
2. **원스톱 강화 제안 (Prompt Enhance 적용)**:
   - **원본 의도**: 사용자가 달성하려는 핵심 목표 1줄 추출
   - **주입 맥락**: 현재 활성 파일, 브랜치, 프로젝트 스택 기반의 확인된 팩트 매핑
   - **구조화 지시문**: 목표, 제약 사항, 완료 기준을 정돈한 강화 프롬프트 1블록 제시
3. **가벼운 확인 후 실행**:
   - 강화본을 보여주고 사용자가 "진행" 또는 기본값 승인 시 즉시 해당 작업으로 착수한다.

## Anti-Patterns (GOTCHAS 준수)

- **과잉 강화 금지**: 원본 의도에 없는 새로운 기능·제약·출력 형식을 지어내지 않는다. 모르면 범위를 좁히거나 묻는다.
- **모든 턴 강제 금지**: 단순 대화나 명확한 1줄 지시까지 매번 강화 핑퐁을 걸어 피로도를 유발하지 않는다.
- **확인 스킵 금지**: 강화본을 사용자에게 보여주지 않고 임의로 실행하지 않는다.
