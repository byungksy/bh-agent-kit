# Prompt Enhance

유형: Encoded Preference (Workflow). 사용자의 거친 발화를 구조화된 프롬프트로 다듬고 확인 후 실행한다.

## 흐름

1. 사용자 발화에서 **원본 의도**를 추출한다
2. 아래 강화 원칙을 적용해 프롬프트를 재구성한다
3. 원본과 강화본을 나란히 보여준다
4. 사용자 확인 후 강화본으로 실행한다

## 입력 형태

```
/prompt-enhance <원본 프롬프트>
# 또는
/프롬프트_보정 <원본 프롬프트>
```

또는 "프롬프트 보정/보완/수정/개선" 등 트리거 키워드 + 프롬프트. 프롬프트가 없으면 한 줄로 묻는다.

## 강화 원칙

순서대로 적용한다. 원본이 이미 충분하면 해당 항목을 건너뛴다.

### 1. 의도 명확화

- 모호한 동사 → 구체적 행위로 교체 ("해줘" → "구현해줘" / "분석해줘" / "설명해줘")
- 대상이 빠졌으면 보충 (현재 프로젝트, 파일, 기능 맥락에서 추론)
- "이거" "그거" 같은 지시어 → 구체적 대상으로 치환

### 2. 맥락 주입

- 현재 작업 맥락(브랜치, 티켓, 최근 변경)이 관련 있으면 포함
- 프로젝트 기술 스택이 관련 있으면 언급
- 단, 원본 의도에 없는 맥락을 과하게 붙이지 않는다

### 3. 구조화

원본이 한 덩어리면 아래 구조로 분리한다:

```
[맥락] — 현재 상황, 배경 (필요할 때만)
[작업] — 구체적으로 무엇을 해야 하는지
[제약] — 지켜야 할 조건, 피해야 할 것 (있을 때만)
[출력] — 기대하는 결과 형태 (있을 때만)
```

모든 항목을 넣지 않는다. 원본에 없는 제약이나 출력 형식을 지어내지 않는다.

### 4. 과잉 제거

- 불필요한 겸양 ("혹시 가능하시면", "시간 되시면") 제거
- 중복 표현 제거
- 에이전트가 이미 아는 일반 상식 제거

## 확인 체크포인트

강화 후 아래 형식으로 보여준다:

```
━━━━ Prompt Enhanced ━━━━
📝 원본:
{원본 프롬프트}

✨ 강화:
{강화된 프롬프트}

📌 변경 요약:
- {무엇을 왜 바꿨는지 1줄씩}

이대로 실행할까요? (y/수정사항/n)
━━━━━━━━━━━━━━━━━━━━━━━━
```

| 응답 | 행동 |
|------|------|
| y / 네 / 실행 | 강화본으로 실행 |
| 수정 내용 | 수정 반영 후 다시 확인 |
| n / 아니 / 원본으로 | 원본 그대로 실행 |

## 하지 않는 것

- 원본 의도를 바꾸지 않는다. 범위를 확장하지 않는다.
- 에이전트의 톤이나 페르소나를 지정하지 않는다 (gaslighting 스킬 영역).
- "step by step으로 생각해" 같은 추론 유도 문구를 기계적으로 붙이지 않는다.
- 원본이 이미 충분히 명확하면 "강화할 게 없다"고 말하고 그대로 실행한다.
