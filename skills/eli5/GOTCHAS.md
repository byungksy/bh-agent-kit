# eli5 GOTCHAS

원본 스킬(`anthropics/claude-plugins-community/eli5`)은 지시가 한 줄뿐이라 실제 실행 시 아래 함정이 반복된다. 발견되는 대로 이 목록에 추가한다.

## 트리거 관련

- **"쉽게 설명해줘"만으로 자동 발동 금지**: 사용자가 텍스트 기반의 간단한 설명을 원하는 것과, HTML 아티팩트를 만들어달라는 것은 다르다. `/eli5` 명시 호출이거나 "그림으로", "비주얼로" 같은 단서가 없으면 먼저 산출물 형태(텍스트 답변 vs HTML 파일)를 확인한다.
- **전문가 대상 요약과 혼동 금지**: "요약해줘", "간단히 설명해줘"는 이 스킬의 대상이 아니다. ELI5는 "선행 지식 0"을 가정한 설명이지 "짧은 설명"이 아니다.

## 출력 품질

- **그림 없는 ELI5는 실패다**: 텍스트만 나열하고 다이어그램/아이콘/비유 이미지가 없으면 원래 목적(큰 그림 + 적은 글자)을 달성하지 못한 것이다. SVG나 이모지, CSS로 그린 도형이라도 시각 요소를 반드시 포함한다.
- **정확도와 단순화의 트레이드오프를 숨기지 않는다**: ELI5는 의도적으로 세부사항을 생략한다. 기술적으로 부정확해질 수 있는 지점(예: "DNS는 전화번호부 같은 것" — 실제로는 캐싱·TTL 등 복잡한 계층이 있음)은 괜찮다. 다만 사용자가 이 결과를 전문적 근거로 쓸 수도 있는 맥락(보고서, 코드 리뷰 등)이면 단순화로 인한 부정확성을 짧게 언급한다.
- **주제 범위를 스스로 좁힌다**: "블록체인이 뭐야" 같은 큰 주제를 통째로 다루면 산출물이 길어지고 ELI5 취지를 벗어난다. 핵심 비유 1~2개로 압축하고, 더 알고 싶으면 후속 질문을 유도한다.

## 산출물 관리

- **저장 경로를 명확히 한다**: HTML 파일을 만들 때 현재 작업 디렉토리에 무분별하게 흩뿌리지 않는다. 별도 요청이 없으면 임시 결과물임을 밝히고, 파일명은 주제를 알 수 있게 짓는다 (예: `eli5-dns.html`).
- **외부 리소스 의존 금지**: CDN 스크립트, 외부 폰트, 외부 이미지 URL을 쓰지 않는다. 오프라인에서도 열려야 하고, 신뢰할 수 없는 외부 요청을 만들지 않는다 (보안 가드레일과도 연결됨).
- **인라인 스크립트에 사용자 입력을 그대로 삽입하지 않는다**: 주제 문자열을 HTML에 넣을 때 이스케이프 없이 삽입하면 XSS 유사 패턴이 될 수 있다. 정적 아티팩트라 위험도는 낮지만, 이후 웹서버로 서빙될 가능성을 배제하지 않는다.

## 스킬 유형 판단

- **Capability Uplift**: 그림 위주 설명 생성은 모델이 원래 잘하는 능력이라, 모델이 발전하면 이 스킬 없이도 자연스럽게 될 가능성이 높다. GOTCHAS가 실질적으로 도움이 안 되는 시점이 오면 스킬 자체의 존속 여부를 재검토한다.
