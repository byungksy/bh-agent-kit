# bh-plainspeak — GOTCHAS

실수하기 쉬운 지점.

## 1. 사실 왜곡 (가장 흔함)
쉽게 쓰려다 조건을 뭉개는 것. 특히:
- 상태 조건: "SCHEDULED|RECORDING만" → "회의 중일 때만"(OK) / "아무 때나"(왜곡).
- 수치·단위·분모: 그대로 옮긴다. 임의 반올림·생략 금지.
- 정책 방향: "필터 우회"를 "필터 강화"로 뒤집는 식의 반대 서술 금지.
→ 5단계 "사실 검증"에서 원문과 1:1 대조.

## 2. 원문 훼손
`{basename}-쉬운설명.md`처럼 **새 파일**을 만든다. 원문 plan.md·스펙을 덮어쓰면 SSOT가 깨진다.

## 3. "쉬운 설명"인데 안 쉬움
- 표/Mermaid를 그대로 붙여넣고 끝내기 → 금지. 문장으로 풀어야 한다.
- 용어를 그대로 두기 → 괄호 한 줄 풀이 필수.

## 4. 톤 과잉
과장·칭찬·이모지 남발은 communication-style 위반. 담백한 구어체만.

## 5. 대상 모호
파일 경로가 없고 직전 맥락도 불명확하면, 추측하지 말고 어떤 문서를 풀지 1문장 확인(inquiry-first).

## 6. 다이어그램이 목적이면
"쉬운 설명"이 아니라 "시각화"를 원하는 거면 `bh-create-workflow`를 쓴다.
